# GO2W ARM 参数优化

## 概述

本文档整理了GO2W ARM机器人的完整参数优化记录，包括初始状态优化、扭矩限制调整、奖励权重调优和算法参数配置等核心内容。

**重要说明**：当前代码中存在完整的两段式恢复框架，但实际训练时使用的是**传统单阶段站立训练**策略。本文档的参数优化是基于单阶段策略的。

---

## 1. 初始状态优化

### 1.1 优化目标

GO2W_ARM机器人在训练中难以从翻倒状态恢复站立，主要原因是：
1. 初始姿态随机化过于激进（±180°的角度和±0.5的角速度）
2. 初始高度过低（0-0.2m，接近地面）
3. 高度奖励函数为负权重（-5.0），实际上是惩罚而不是奖励
4. 垂直运动惩罚（lin_vel_z_l2）与恢复需要的向上动量冲突

### 1.2 位置范围优化

**修改文件**: `velocity_env_cfg.py`

```python
# 位置范围修改
"x": (-0.5, 0.5) → (-0.2, 0.2)     # ±0.5m → ±0.2m（减小60%）
"y": (-0.5, 0.5) → (-0.2, 0.2)     # ±0.5m → ±0.2m（减小60%）
"z": (0.0, 0.2) → (0.35, 0.5)       # 0-0.2m → 0.35-0.5m（提高75%）
```

**优化效果对比**:

| 参数 | 修改前 | 修改后 | 改进幅度 | 物理意义 |
|------|--------|--------|----------|----------|
| 位置X范围 | ±0.5m | ±0.2m | ⬇️ 60% | 减小初始偏离 |
| 位置Y范围 | ±0.5m | ±0.2m | ⬇️ 60% | 减小初始偏离 |
| 高度Z范围 | 0-0.2m | 0.35-0.5m | ⬆️ 75% | 从趴伏状态开始 |

### 1.3 姿态角度优化

**关键发现**：对于两段式恢复策略，初始姿态应该是侧卧状态（roll: -1.5~1.5），而不是小角度。

```python
# 姿态角度修改
"roll": (-3.14, 3.14) → (-0.3, 0.3)     # ±180° → ±17°（减小90%）
"pitch": (-3.14, 3.14) → (-0.3, 0.3)    # ±180° → ±17°（减小90%）
"yaw": (-3.14, 3.14) → (-3.14, 3.14)     # ±180° → ±180°（保持完全随机）
```

**物理意义分析**：
- 当前配置：小角度（±17°），适合单阶段站立训练
- 两段式需要：大角度（±90°），模拟侧卧状态
- 问题：当前单阶段策略无法处理大角度侧卧恢复

**优化效果对比**:

| 参数 | 修改前 | 修改后 | 改进幅度 | 适用策略 |
|------|--------|--------|----------|----------|
| 翻滚角范围 | ±180° | ±17° | ⬇️ 90% | 单阶段 |
| 俯仰角范围 | ±180° | ±17° | ⬇️ 90% | 单阶段 |
| 航向角范围 | ±180° | ±180° | ➡️ 保持 | 所有策略 |

### 1.5 奖励函数调整

#### 问题分析

**高度奖励** (`velocity_env_cfg.py`):
```python
# 高度奖励修改
self.rewards.base_height_l2.weight = -5.0 → 2.0   # 从惩罚改为奖励
self.rewards.base_height_l2.params["target_height"] = 0.40 → 0.42  # 调整目标高度
```

**垂直运动惩罚问题**：
```python
# 当前配置
self.rewards.lin_vel_z_l2.weight = -0.1
```

**物理冲突**：
- `lin_vel_z_l2` 惩罚垂直速度（weight=-0.1）
- 但侧卧恢复需要向上的速度产生向上动量
- 这导致策略被抑制，无法学习起跳

**直立姿态奖励** (`velocity_env_cfg.py`):
```python
# 直立姿态奖励修改
self.rewards.flat_orientation_l2.weight = 0.0 → 3.0  # 从禁用改为激活
```

**优化效果对比**:

| 奖励项 | 修改前 | 修改后 | 改进说明 | 物理意义 |
|--------|--------|--------|----------|----------|
| base_height_l2 | -5.0（惩罚） | 2.0（奖励） | 改为正向激励 | 鼓励达到站立高度 |
| base_height_l2目标 | 0.40m | 0.42m | 调整到更合理的站立高度 | 匹配机器人几何 |
| flat_orientation_l2 | 0.0（禁用） | 3.0（激活） | 鼓励保持直立姿态 | Z轴对齐世界Z轴 |
| lin_vel_z_l2 | -2.0 | -0.1 | 减小但仍有冲突 | ⚠️ 与恢复任务冲突 |

## 2. 扭矩限制优化

### 2.1 优化目标

GO2W（15kg）+ ARX5机械臂（5kg）= 总重20kg，需要更强的关节扭矩来支持：
- 更快的姿态恢复
- 更强的抗干扰能力
- 更稳定的平衡控制

### 2.2 腿部关节扭矩

```python
# unitree.py - UNITREE_GO2W_ARM_ARX5_CFG
"legs": DelayedPDActuatorCfg(
    effort_limit_sim=35.0,  # 从23.5提高到35.0 N·m (增加49%)
    # 其他参数保持不变
)
```

**物理意义**：
- 23.5 N·m是GO2W的额定扭矩
- 35.0 N·m是接近峰值扭矩
- 增加49%提供更强的姿态恢复能力
- 支撑20kg总重更轻松

### 2.3 轮子关节扭矩

```python
# unitree.py - UNITREE_GO2W_ARM_ARX5_CFG
"wheels": ImplicitActuatorCfg(
    effort_limit_sim=35.0,  # 从23.5提高到35.0 N·m (增加49%)
    # 其他参数保持不变
)
```

**物理意义**：
- 轮子扭矩影响摩擦力产生
- 更大的扭矩可以产生更大的地面摩擦力
- 辅助姿态调整和恢复

### 2.4 机械臂关节扭矩

```python
# unitree.py - UNITREE_GO2W_ARM_ARX5_CFG
"arm": DelayedPDActuatorCfg(
    effort_limit_sim={
        "arm_joint1": 25.0,  # 从20.0提高到25.0 N·m (增加25%)
        "arm_joint2": 25.0,  # 从20.0提高到25.0 N·m (增加25%)
        "arm_joint3": 25.0,  # 从20.0提高到25.0 N·m (增加25%)
        "arm_joint4": 15.0,  # 从10.0提高到15.0 N·m (增加50%)
        "arm_joint5": 15.0,  # 从10.0提高到15.0 N·m (增加50%)
        "arm_joint6": 15.0,  # 从10.0提高到15.0 N·m (增加50%)
    },
    # 其他参数保持不变
)
```

**物理意义**：
- 基座关节（1-3）：承受更大负载，需要25 N·m
- 末端关节（4-6）：负载较小，15 N·m足够
- 机械臂保持紧凑状态，不需要过大扭矩

### 2.5 扭矩限制对比表

| 关节组 | 修改前 | 修改后 | 增加幅度 | 物理意义 |
|--------|--------|--------|----------|----------|
| **腿部关节** | 23.5 N·m | 35.0 N·m | ⬆️ 49% | 更强的姿态恢复能力 |
| **轮子关节** | 23.5 N·m | 35.0 N·m | ⬆️ 49% | 更强的驱动力 |
| **机械臂1-3** | 20.0 N·m | 25.0 N·m | ⬆️ 25% | 更稳定的机械臂控制 |
| **机械臂4-6** | 10.0 N·m | 15.0 N·m | ⬆️ 50% | 更好的末端控制 |

### 2.6 扭矩物理合理性验证

**GO2W电机参数**:
- 额定扭矩: ~23.5 N·m
- 峰值扭矩: ~35-40 N·m

**ARX5机械臂扭矩合理性**:
- 基座关节（1-3）: 20-25 N·m
- 末端关节（4-6）: 10-15 N·m

**结论**: ✅ 所有扭矩设置在电机规格范围内
- 腿部和轮子使用35.0 N·m（接近峰值）
- 机械臂基座使用25.0 N·m（额定值）
- 机械臂末端使用15.0 N·m（保守值）

## 3. 机械臂姿态优化

### 3.1 优化目标

减少机械臂在训练初期对平衡的干扰：
- 收起机械臂，降低质心高度
- 减少机械臂运动产生的动量
- 让机器人先学会腿部平衡

## 7. 扭矩惩罚参数

### 7.1 关键参数

| 参数 | 值 | 说明 | 物理意义 |
|------|-----|------|----------|
| **sustained_window** | 2.0秒 | 持续超出时间窗口 | 只有持续2秒以上才惩罚 |
| **burst_threshold** | 1.5倍 | 瞬发扭矩阈值 | 允许瞬时1.5倍额定扭矩 |
| **decay_rate** | 0.9 | 衰减率 | 控制历史扭矩的影响 |
| **rated_torque** | 23.5 N·m | 额定扭矩 | GO2W电机的额定扭矩 |

### 7.2 扭矩惩罚物理逻辑

```python
def torque_penalty(env, asset_cfg, sustained_window=2.0,
                burst_threshold=1.5, decay_rate=0.9, rated_torque=23.5):
    # 获取当前扭矩
    current_torque = torch.abs(asset.data.applied_torque[:, asset_cfg.joint_ids])

    # 指数移动平均
    env.torque_history = decay_rate * env.torque_history + (1 - decay_rate) * current_torque

    # 计算超出持续时间
    is_over_limit = env.torque_history > (rated_torque * burst_threshold)  # 35.25 N·m
    env.torque_counter = torch.where(is_over_limit, env.torque_counter + 1, 0)

    # 计算持续超出时间（秒）
    sustained_time = env.torque_counter * env.step_dt

    # 只惩罚持续超出时间窗口的情况
    over_window = sustained_time > sustained_window  # > 2.0秒

    # 惩罚值 = 超出幅度 * 持续时间
    exceed_amount = env.torque_history - rated_torque
    penalty = over_window.float() * exceed_amount * sustained_time

    return -torch.sum(penalty, dim=-1)
```

**物理意义**：
1. **瞬时峰值允许**：允许起跳瞬间的爆发扭矩（< 2秒）
2. **持续过热保护**：惩罚持续超出额定扭矩的行为
3. **平滑阈值**：使用指数移动平均避免噪声触发

### 7.3 物理合理性验证

**GO2W电机参数**:
- 额定扭矩: ~23.5 N·m
- 峰值扭矩: ~35-40 N·m
- 短时过载: 1.5倍额定（~35 N·m）可持续数秒

**ARX5机械臂扭矩合理性**:
- 基座关节（1-3）: 额定20-25 N·m，峰值35-40 N·m
- 末端关节（4-6）: 额定10-15 N·m，峰值20-25 N·m

**结论**: ✅ 所有扭矩设置在电机规格范围内
- 瞬时峰值：35.25 N·m（23.5 × 1.5）
- 持续工作：23.5 N·m（额定值）
- 时间窗口：2.0秒（电机短时过载能力）

## 8. 关节正则化参数

### 8.1 关键参数

| 参数 | 值 | 说明 | 物理意义 |
|------|-----|------|----------|
| **soft_ratio** | 0.95 | 距离极值95%时开始惩罚 | 预留5%缓冲空间 |
| **权重** | 0.5 | 惩罚强度 | 中等强度 |

### 8.2 关节正则化物理逻辑

```python
def joint_regularization(env, asset_cfg, soft_ratio=0.95):
    # 获取关节位置和限位
    joint_pos = asset.data.joint_pos[:, asset_cfg.joint_ids]
    joint_limits = asset.data.joint_pos_limits

    # 计算每个关节在限位范围内的位置百分比
    range_size = limits_upper - limits_lower
    normalized_pos = (joint_pos - limits_lower) / range_size

    # 计算距离最近限位的最小距离
    dist_to_lower = normalized_pos
    dist_to_upper = 1.0 - normalized_pos
    min_dist = torch.minimum(dist_to_lower, dist_to_upper)

    # 软限位：只惩罚小于soft_ratio的距离
    safe_zone = soft_ratio  # 0.95
    penalty_zone = torch.clamp(safe_zone - min_dist, min=0.0)

    # 使用指数函数增强惩罚
    penalty = torch.sum(torch.exp(penalty_zone * 10.0), dim=-1)

    return -penalty
```

**物理意义**：
1. **避免卡死**：预留5%缓冲空间，防止达到限位
2. **运动灵活性**：保持在关节限位内有一定余量
3. **安全性**：避免在极端位置工作，减少关节磨损
4. **指数增强**：越接近限位惩罚越重

## 11. 故障排除

- 扭矩仍不足

- lin_vel_z_l2与恢复任务冲突

1. 进一步增大扭矩到45.0 N·m
2. 降低随机化范围
3. 调整奖励权重优先级
4. 减小或移除lin_vel_z_l2惩罚

#### 问题：机械臂仍然干扰平衡

- 机械臂姿态不够紧凑

- 动作空间包含过多机械臂关节

1. 进一步收起机械臂（arm_joint2=0.0, arm_joint3=0.0）
2. 降低机械臂刚度
3. 增加机械臂稳定性奖励
4. 从动作空间移除机械臂关节

#### 问题：扭矩利用率过低

**可能原因**:
- 扭矩限制过大，浪费资源
- 动作scale过小
- 奖励函数限制了扭矩使用

**解决方案**:
1. 降低扭矩限制到30.0 N·m
2. 增大动作scale
3. 调整执行器增益

1. 进一步增大扭矩到45.0 N·m
