# GO2W-ARM 两段式恢复训练配置详解

## 概述

本文档详细描述了 GO2W-ARM 机器人两段式恢复训练的完整配置，包括执行策略、观测空间、奖励函数、课程学习、事件系统以及训练的物理逻辑。该配置基于 `robot_lab_locomanip` 参考项目，并针对轮足复合机器人的特点进行了优化。

## 1. 执行策略 (Actions)

### 1.1 双动作空间设计

GO2W-ARM 采用**混合动作空间**，结合位置控制和速度控制：

```python
# 位置控制：腿 + 所有机械臂关节（动态甩动）
joint_pos: JointPositionActionCfg
- 控制关节：12条腿关节 + 6个机械臂关节（全激活）
- 缩放因子：差异化缩放（针对恢复训练优化）
  - 髋关节：0.125（更精细的控制）
  - 机械臂根部 (arm_joint1)：0.5（增大5倍，允许快速甩动产生惯性力矩）
  - 其他关节：0.25
- 使用默认偏移量
- 裁剪范围：(-100.0, 100.0)

# 速度控制：轮子
joint_vel: JointVelocityActionCfg
- 控制关节：4个轮子关节
- 缩放因子：5.0
- 使用默认偏移量
- 裁剪范围：(-100.0, 100.0)
```

### 1.2 物理逻辑

**动作映射关系**：
```
动作空间维度 = 18 (位置) + 4 (速度) = 22

位置控制 (18维):
├── 腿部 (12维)
│   ├── FR_hip_joint, FR_thigh_joint, FR_calf_joint
│   ├── FL_hip_joint, FL_thigh_joint, FL_calf_joint
│   ├── RR_hip_joint, RR_thigh_joint, RR_calf_joint
│   └── RL_hip_joint, RL_thigh_joint, RL_calf_joint
└── 机械臂 (6维) - 全激活，允许动态甩动借力
    ├── arm_joint1 (根部旋转)
    ├── arm_joint2
    ├── arm_joint3
    ├── arm_joint4
    ├── arm_joint5
    └── arm_joint6

速度控制 (4维):
├── FR_foot_joint
├── FL_foot_joint
├── RR_foot_joint
└── RL_foot_joint
```

**控制策略原理**：
- **腿部位置控制**：提供精确的姿态调整能力，用于站立、平衡和步态规划
- **轮子速度控制**：提供连续的推进力，用于移动和转向
- **机械臂动态甩动**：利用6个自由度的机械臂进行动态甩动，产生恢复所需的动量和力矩
  - **全关节激活**：所有6个机械臂关节都参与控制，而非仅根部关节
  - **动量传递**：通过手臂的甩动产生旋转动量，辅助身体从侧卧状态恢复
  - **重心调整**：手臂位置变化可以快速调整重心，辅助平衡
  - **支撑辅助**：手臂可以作为额外的支撑点，在恢复过程中提供稳定性
- **动态借力策略**：在倒地时，机械臂甩动可以产生额外的恢复力矩
  - **爆发式动作**：利用自适应惩罚系统，在倒下状态允许大幅度的手臂动作
  - **协调性**：手臂动作与腿部、轮子动作协调，产生复合恢复力

**动作缩放的物理意义**：
- 较小的缩放因子（0.1, 0.125）意味着更精细的控制，适用于需要高精度的关节
- 较大的缩放因子（0.25）允许更大的动作幅度，适用于大范围运动
- 速度控制缩放因子（5.0）将动作值映射到实际角速度范围

### 1.3 arm_joint1 缩放因子特殊处理

**缩放因子调整**：
- **原始配置**：0.1（精细控制，适用于精确操作）
- **恢复训练配置**：0.5（增大5倍，专为恢复训练优化）
- **调整原因**：机械臂根部承载整个机械臂的质量（大质量），小缩放因子难以产生足够的惯性力矩

**物理原理**：

#### 1.3.1 惯性力矩计算

机械臂根部急甩产生的惯性力矩：

```
τ_inertial = I_arm × α_arm
```

其中：
- `I_arm`：机械臂相对于根部的转动惯量（大质量，大惯量）
- `α_arm`：机械臂根部的角加速度

**缩放因子的影响**：
```
α_arm ∝ (action × scale)²
```

缩放因子从 0.1 增加到 0.5：
- 角加速度增加：(0.5/0.1)² = **25 倍**
- 惯性力矩增加：**25 倍**

#### 1.3.2 打破静态平衡

**侧卧状态**：
- 机器人倒在一侧，重心偏离支撑区域
- 静态力矩：τ_static = m × g × d（质量 × 重力 × 重心偏移）
- 需要额外的动态力矩来打破静态平衡

**惯性力矩作用**：
```
τ_total = τ_static + τ_inertial
```

当 `τ_inertial` 足够大时，可以推动重心回到支撑区域内，触发翻滚恢复。

#### 1.3.3 恢复策略示例

**右侧卧（roll ≈ +90°）**：
1. 机械臂向左急甩（arm_joint1 快速旋转）
2. 产生向右的惯性力矩（角动量守恒）
3. 推动机体向右翻滚
4. 配合轮子角动量、腿部动作，完成恢复

**左侧卧（roll ≈ -90°）**：
1. 机械臂向右急甩
2. 产生向左的惯性力矩
3. 推动机体向左翻滚

#### 1.3.4 与其他恢复机制的协同

**轮子角动量**（权重 2.0）：
- 产生翻滚扭矩（力矩）
- 适用于悬空轮子

**机械臂惯性力矩**：
- 产生惯性力矩（力矩）
- 适用于大质量机械臂的快速甩动
- 与轮子角动量协同，产生复合恢复力矩

**自适应惩罚系统**：
- 在倒下状态（Z < 0.5），惩罚权重降低 10 倍
- 允许机械臂产生大幅度的甩动动作
- 允许机械臂产生大的角加速度

#### 1.3.5 配置细节

```python
self.actions.joint_pos.scale = {
    ".*_hip_joint": 0.125,      # 髋关节保持精细控制
    "arm_joint1": 0.5,           # 机械臂根部增大至 0.5
    "^(?!.*_hip_joint)(?!arm_joint1).*": 0.25,  # 其他关节
}
```

**优先级说明**：
1. `arm_joint1` 优先匹配，使用 0.5
2. `.*_hip_joint` 优先匹配，使用 0.125
3. 其他所有关节使用 0.25

#### 1.3.6 预期效果

**动作幅度**：
- 原始配置（scale=0.1）：小幅度精细动作
- 恢复配置（scale=0.5）：大幅度快速动作

**惯性力矩**：
- 原始配置：τ_inertial_original ∝ 0.01
- 恢复配置：τ_inertial_recovery ∝ 0.25
- 增加倍数：**25 倍**

**恢复成功率**：
- 原始配置：可能因惯性力矩不足，难以打破静态平衡
- 恢复配置：能够产生足够的惯性力矩，有效打破静态平衡

## 3. 奖励函数 (Rewards)

### 3.1 激活奖励项及权重

#### 3.1.1 速度跟踪奖励（正奖励）

| 奖励项 | 权重 | 物理意义 | 计算方法 |
|--------|------|----------|----------|
| `track_lin_vel_xy_exp` | 3.0 | 线速度跟踪 | `exp(-|v_actual - v_cmd|² / σ²)` |
| `track_ang_vel_z_exp` | 1.5 | 角速度跟踪 | `exp(-|ω_actual - ω_cmd|² / σ²)` |

**总最大正奖励**：4.5（当完美跟踪时）

**物理逻辑**：
- 使用指数奖励函数，小误差时仍有奖励，大误差时奖励快速衰减
- 标准差 σ = 0.5，决定了奖励的敏感度
- 线速度权重更高，因为移动是主要目标

#### 3.1.2 基础状态惩罚（负奖励）

| 奖励项 | 权重 | 物理意义 | 说明 |
|--------|------|----------|------|
| `lin_vel_z_l2` | -2.0 | Z轴线速度惩罚 | 避免不必要的垂直运动 |
| `base_height_l2` | -5.0 | 高度偏离惩罚 | 目标高度 0.40m |

**物理逻辑**：
- **lin_vel_z_l2**：Z轴速度应接近0，除非需要跳跃或恢复
- **base_height_l2**：保持稳定的站立高度，过高的Z速度会导致不稳定

#### 3.1.3 关节惩罚（负奖励）

| 奖励项 | 权重 | 作用关节 | 物理意义 |
|--------|------|----------|----------|
| `joint_torques_l2` | -2.5e-5 | 腿 + 臂 | 能量效率，减少扭矩消耗 |
| `joint_acc_l2` | -2.5e-7 | 所有关节 | 平滑运动，减少加速度冲击 |
| `joint_pos_limits` | -5.0 | 腿 + 臂 | 安全性，避免关节限位 |
| `joint_power` | -2.0e-5 | 腿 + 臂 | 功率惩罚，能量效率 |

**物理逻辑**：
- **扭矩惩罚**：较小的权重（1e-5级别）允许必要的扭矩，但惩罚过大的扭矩
- **加速度惩罚**：极小的权重（1e-7级别）鼓励平滑的运动轨迹
- **位置限位惩罚**：较大的权重（-5.0）严格防止关节达到机械限位
- **功率惩罚**：功率 = 扭矩 × 速度，鼓励高效的运动模式

#### 3.1.4 动作惩罚（负奖励）

| 奖励项 | 权重 | 物理意义 |
|--------|------|----------|
| `action_rate_l2` | -0.01 | 动作变化率惩罚，鼓励平滑的动作序列 |

**物理逻辑**：
- 防止策略产生剧烈的动作抖动
- 提高运动平滑性和可预测性
- 减少控制器输出噪声

#### 3.1.5 接触惩罚（负奖励）

| 奖励项 | 权重 | 物理意义 | 阈值 |
|--------|------|----------|------|
| `undesired_contacts` | -1.0 | 非脚部接触惩罚 | 1.0 N |
| `contact_forces` | -1.5e-4 | 脚部接触力惩罚 | 100.0 N |

**物理逻辑**：
- **undesired_contacts**：惩罚膝盖、身体等部位接触地面，只允许脚部接触
- **contact_forces**：防止过大的脚部接触力，保护机器人硬件

#### 3.1.6 恢复奖励（正奖励）

| 奖励项 | 权重 | 物理意义 | 计算方法 |
|--------|------|----------|----------|
| `upward` | 5.0 | 姿态直立奖励 | `projected_gravity[:, 2]` |

**物理逻辑**：
- **upward_orientation**：基于 `projected_gravity` 的 Z 分量，直接反映姿态的直立程度
  - Z = 1.0：完全直立，奖励 = 5.0（最大）
  - Z = 0.5：倾斜 60°，奖励 = 2.5
  - Z = 0.0：倒下，奖励 = 0.0
- **高权重设计**：权重 5.0 是所有奖励中最高的，强烈鼓励机器人保持直立姿态
- **恢复促进**：当机器人从侧卧（Z ≈ 0）向直立（Z ≈ 1）恢复时，奖励持续增加
- **与Z速度的权衡**：与 `lin_vel_z_l2` 惩罚（-2.0）形成平衡 - 只在需要时产生向上的速度
- **姿态优先**：相比向上速度，姿态直立度是更根本的目标

**物理意义**：
- 基于 `projected_gravity` 的 Z 分量，这是姿态的最直接指标
- 鼓励机器人从不稳定状态（低Z）快速恢复到稳定状态（高Z）
- 在侧倾恢复场景中（roll ∈ ±90°），这个奖励是关键驱动力

#### 3.1.7 轮子角动量奖励（正奖励）

| 奖励项 | 权重 | 物理意义 | 计算方法 |
|--------|------|----------|----------|
| `wheel_angular_momentum` | 2.0 | 悬空轮子急加速奖励 | 悬空轮子的角加速度之和 |

**函数实现**：
```python
def wheel_angular_momentum_reward(
    env: ManagerBasedRLEnv,
    asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"),
    sensor_cfg: SceneEntityCfg = SceneEntityCfg("contact_forces"),
    wheel_joint_names: list = None,
    weight: float = 1.0,
    contact_threshold: float = 1.0,
) -> torch.Tensor
```

**参数说明**：
- `env`: 强化学习环境
- `asset_cfg`: 机器人资产配置
- `sensor_cfg`: 接触传感器配置
- `wheel_joint_names`: 轮子关节名称列表（FR_foot_joint, FL_foot_joint, RR_foot_joint, RL_foot_joint）
- `weight`: 奖励权重（配置中设置为 2.0）
- `contact_threshold`: 接触力阈值（1.0 N，低于此值认为轮子悬空）

**物理原理**：

##### 3.1.7.1 角动量守恒定律

```
L_total = L_body + L_wheels = constant
```

当轮子急加速时（ΔL_wheels > 0），为保持总角动量守恒，机身必须获得反向的角动量（ΔL_body < 0），即产生反向扭矩。

**关键机制**：
- **角动量传递**：轮子加速 → 机身获得反向角动量 → 产生翻滚扭矩
- **悬空轮子效应**：只有悬空的轮子才能产生有效的翻滚扭矩，接触地面的轮子的扭矩会被地面反作用力抵消
- **翻滚辅助**：在侧卧状态下，悬空轮子的急加速可以辅助机体翻滚脱困

##### 3.1.7.2 奖励计算流程

```python
1. 获取姿态指标: uprightness = projected_gravity[:, 2]
2. 判断是否倾斜: is_tilted = (uprightness < 0.5)
3. 获取轮子速度: current_wheel_vel = joint_vel[:, wheel_joint_ids]
4. 计算角加速度: wheel_acceleration = current_wheel_vel - last_wheel_vel
5. 检测悬空轮子: is_airborne = (contact_force < 1.0)
6. 计算奖励: reward = sum(abs(wheel_acceleration) * is_airborne) * is_tilted * weight
```

**姿态条件**：
- **Z < 0.5**：给予奖励（严重倾斜，需要恢复）
- **Z ≥ 0.5**：不给予奖励（相对稳定，不需要轮子急加速）

这种设计确保轮子角动量奖励只在需要恢复时激活，避免在正常运动中产生不必要的轮子加速。

##### 3.1.7.3 策略应用场景

**场景 1: 右侧卧（roll ≈ +90°）**
- **悬空轮子**: 左侧轮子（FL, RL）悬空
- **策略动作**: 左侧轮子向前急加速
- **物理效果**: 产生向右翻滚的扭矩
- **结果**: 机体从右侧卧翻滚向直立

**场景 2: 左侧卧（roll ≈ -90°）**
- **悬空轮子**: 右侧轮子（FR, RR）悬空
- **策略动作**: 右侧轮子向前急加速
- **物理效果**: 产生向左翻滚的扭矩
- **结果**: 机体从左侧卧翻滚向直立

**场景 3: 前倾（pitch ≈ +90°）**
- **悬空轮子**: 后轮（RR, RL）悬空
- **策略动作**: 后轮急加速
- **物理效果**: 产生向前翻滚的扭矩
- **结果**: 机体从前倾翻滚向直立

##### 3.1.7.4 物理逻辑

- **侧卧状态**：当机器人侧卧时（roll ∈ ±90°），某些轮子会悬空
- **急加速策略**：策略学习到让悬空轮子急加速，产生反向扭矩
- **翻滚效果**：反向扭矩辅助机体从不稳定的侧卧状态翻滚到更稳定的状态
- **与upward奖励配合**：轮子角动量产生翻滚，upward奖励鼓励直立姿态

##### 3.1.7.5 与其他奖励的协同

**与 upward 奖励的协同**：
- **wheel_angular_momentum**: 产生翻滚扭矩，改变姿态
- **upward**: 奖励直立姿态（projected_gravity Z 分量）
- **协同效果**: 轮子角动量帮助翻滚 → 姿态改善 → upward 奖励增加

**与自适应惩罚的协同**：
- **倒下状态（Z < 0.5）**：

  - wheel_angular_momentum 激活
  - 策略可以"疯狂"探索翻滚动作
- **直立状态（Z > 0.8）**：
  - 惩罚权重恢复
  - wheel_angular_momentum 不激活
  - 策略保持平滑运动

**与机械臂动态的协同**：
- **机械臂甩动**: 产生额外的恢复力矩（arm_joint1 缩放因子 0.5）
- **轮子角动量**: 产生翻滚扭矩
- **协同效果**: 多个恢复机制同时工作，提高恢复成功率

### 3.3 奖励函数的物理意义总结

**主要目标**：
1. **姿态恢复**（权重 +7.0）：通过姿态直立奖励（+5.0）和轮子角动量奖励（+2.0）促进从倾斜/侧卧状态恢复
2. **速度跟踪**（权重 +4.5）：确保机器人能够准确执行速度命令
3. **姿态稳定**（权重 -7.0）：通过高度、Z速度和重力投影保持直立
4. **安全性**（权重 -6.0）：通过关节限位和接触保护保护机器人
5. **能量效率**（权重 ~-4.5e-5）：通过扭矩和功率惩罚减少能量消耗
6. **平滑性**（权重 -0.01）：通过动作变化率惩罚提高运动质量

**平衡策略**：
- 正奖励（姿态恢复 + 速度跟踪）引导机器人完成任务和恢复能力
- 负奖励（各种惩罚）约束机器人的行为在合理范围内
- 权重比例反映了任务优先级：姿态恢复 > 速度跟踪 > 安全性 > 能量效率 > 平滑性

**奖励权重对比表**：

| 奖励项 | 权重 | 作用 | 优先级 |
|--------|------|------|--------|
| `upward` | +5.0 | 姿态直立奖励（最高优先级） | 🔴 最高 |
| `wheel_angular_momentum` | +2.0 | 轮子角动量奖励（翻滚辅助） | 🟠 高 |
| `track_lin_vel_xy_exp` | +3.0 | 线速度跟踪奖励 | 🟡 中 |
| `track_ang_vel_z_exp` | +1.5 | 角速度跟踪奖励 | 🟢 低 |

**权重设计理由**：
1. **upward (5.0)**：最高权重，直接反映最终目标（直立姿态）
2. **wheel_angular_momentum (2.0)**：高权重，鼓励有效的翻滚策略，利用角动量守恒
3. **速度跟踪 (3.0 + 1.5)**：中等权重，确保基本运动能力

**两段式恢复的奖励设计**：
- **upward_orientation 奖励**（+5.0）：当 roll 角大幅放开至 ±90° 时，这个奖励成为关键
  - 基于 `projected_gravity` 的 Z 分量，直接反映姿态直立程度
  - 从侧卧状态（Z≈0，roll≈±90°）向直立状态（Z≈1）恢复时，奖励持续增加
  - 高权重（5.0）使其成为最强的正奖励，引导策略优先恢复直立姿态
  - 与 lin_vel_z_l2 惩罚（-2.0）形成权衡：只在需要时产生向上的速度

### 3.4 自适应惩罚系统（Adaptive Penalty System）

为了支持两段式恢复训练，特别是从侧卧状态（Z < 0.5）的恢复，引入了**自适应惩罚系统**。该系统根据机器人的姿态（`projected_gravity` 的 Z 分量）动态调整惩罚权重。

#### 3.4.1 自适应原理

**姿态阈值**：
- **严重倾斜/倒下**：`projected_gravity[:, 2] < 0.5`（Z < 0.5）
  - 对应 roll 角约 ±60° 到 ±90°
  - 机器人处于不稳定状态，需要"疯狂探索"来产生恢复动量
- **过渡区域**：`0.5 ≤ projected_gravity[:, 2] ≤ 0.8`
  - 惩罚权重从 0.1x 线性插值到 1.0x
- **直立状态**：`projected_gravity[:, 2] > 0.8`（Z > 0.8）
  - 机器人接近直立，恢复平滑性和能量效率

#### 3.4.2 自适应惩罚函数

##### 3.4.2.1 动作变化率自适应惩罚

| 参数 | 值 | 物理意义 |
|------|-----|----------|
| `full_penalty_weight` | -0.01 | 直立状态下的完整惩罚 |
| `reduced_penalty_weight` | -0.001 | 倒下状态下的惩罚（10x 降低） |
| `orientation_threshold` | 0.5 | 姿态阈值，触发自适应调整 |

**物理逻辑**：
- **倒下时**（Z < 0.5）：惩罚权重降低 10 倍，允许策略产生剧烈的动作变化
- **直立时**（Z > 0.8）：恢复完整惩罚，确保动作平滑
- **过渡时**（0.5 ≤ Z ≤ 0.8）：权重线性插值，平滑过渡

##### 3.4.2.2 扭矩自适应惩罚

| 参数 | 值 | 物理意义 |
|------|-----|----------|
| `full_penalty_weight` | -2.5e-5 | 直立状态下的完整惩罚 |
| `reduced_penalty_weight` | -2.5e-6 | 倒下状态下的惩罚（10x 降低） |
| `orientation_threshold` | 0.5 | 姿态阈值，触发自适应调整 |

**物理逻辑**：
- **倒下时**：允许产生大扭矩，用于产生恢复所需的动量
- **直立时**：限制扭矩，优化能量效率
- **支持爆发动作**：在恢复初期允许使用"爆发式"大扭矩动作

##### 3.4.2.3 接触自适应惩罚

| 参数 | 值 | 物理意义 |
|------|-----|----------|
| `full_penalty_weight` | -1.0 | 直立状态下的完整惩罚 |
| `reduced_penalty_weight` | -0.1 | 倒下状态下的惩罚（10x 降低） |
| `orientation_threshold` | 0.5 | 姿态阈值，触发自适应调整 |

**物理逻辑**：
- **倒下时**：允许身体其他部位接触地面，用于支撑和滚动
- **直立时**：严格限制非脚部接触，保护机器人硬件
- **支持恢复动作**：允许使用身体滚动、手臂支撑等恢复策略

#### 3.4.3 自适应惩罚的物理意义

**"疯狂探索"阶段**（Z < 0.5）：
- 惩罚权重降低 10 倍
- 允许策略产生大幅度的动作变化
- 允许产生大扭矩和爆发力
- 允许身体其他部位接触地面
- **目标**：在倒下状态快速探索有效的恢复动量

**平滑恢复阶段**（Z > 0.8）：
- 恢复完整惩罚权重
- 确保动作平滑和可预测
- 优化能量效率
- 限制非必要接触
- **目标**：保持稳定、高效的运动

**过渡阶段**（0.5 ≤ Z ≤ 0.8）：
- 权重线性插值，平滑过渡
- 避免惩罚权重突变导致的策略不连续
- **目标**：平稳地从探索阶段过渡到恢复阶段

#### 3.4.4 自适应系统的优势

1. **支持恢复探索**：在倒下状态允许"疯狂"的动作探索
2. **保持运动质量**：在直立状态确保平滑性和能量效率
3. **避免局部最优**：降低惩罚有助于跳出局部最优
4. **物理合理性**：根据姿态状态调整约束，更符合实际恢复需求
5. **训练稳定性**：平滑的权重过渡避免了策略震荡

### 6.3 控制策略物理原理

#### 6.3.1 速度跟踪控制

**期望速度**：通过 `velocity_commands` 给定
- 线速度：vx, vy ∈ [-1.0, 1.0] m/s
- 角速度：ωz ∈ [-1.0, 1.0] rad/s

**控制方法**：
1. **轮子速度控制**：主要推进方式
   - 前进速度：所有轮子同向旋转
   - 转向：左右轮差速旋转
   - 侧向移动：利用腿的姿态调整实现

2. **腿部姿态调整**：辅助控制
   - 重心调整：通过改变腿的长度分配重心
   - 稳定性：调整腿部姿态保持平衡
   - 步态：交替抬腿实现行走

**物理约束**：
- **最大速度限制**：通过奖励函数的指数衰减限制
- **加速能力**：受轮子扭矩和地面摩擦限制
- **稳定性限制**：高速时需要调整重心保持平衡

#### 6.3.2 姿态稳定控制

**姿态指标**：`projected_gravity`
- 完全直立：(0, 0, 1)
- 完全倒下：(0, 0, 0) 或接近
- 侧倾：x分量增大
- 前后倾：y分量增大

**稳定机制**：
1. **重心控制**：通过腿部长度调整重心位置
2. **惯性控制**：利用身体的转动惯量抵抗扰动
3. **支撑多边形**：确保重心在支撑区域内

**物理意义**：
- **高度惩罚** (`base_height_l2`)：保持合理的高度
- **Z速度惩罚** (`lin_vel_z_l2`)：避免不必要的垂直运动
- **重力投影**：关键的状态信息，直接反映姿态

#### 6.3.3 能量效率优化

**能量消耗**：
- **关节扭矩**：`joint_torques_l2` 惩罚
- **关节功率**：`joint_power` 惩罚（扭矩 × 速度）
- **关节加速度**：`joint_acc_l2` 惩罚（间接减少能量消耗）

**优化策略**：
1. **最小化扭矩**：使用重力辅助，避免对抗重力
2. **平滑运动**：减少加速度和加加速度
3. **惯性利用**：利用动量减少主动控制

**物理逻辑**：
- 小的扭矩惩罚允许必要的扭矩
- 功率惩罚鼓励低速运动
- 加速度惩罚鼓励平滑轨迹

### 6.4 两段式恢复的物理逻辑

**虽然当前配置名为"两段式恢复"，但实际上是基于 `robot_lab_locomanip` 的速度跟踪配置。**

#### 6.4.1 当前实现（速度跟踪）

**主要目标**：
1. 准确跟踪速度命令
2. 保持姿态稳定
3. 能量高效运动

**物理机制**：
- **轮子提供主要推进力**
- **腿部调整姿态和重心**
- **机械臂辅助平衡**

#### 6.4.2 两段式恢复的物理原理（当前实现）

**当前配置专门针对两段式恢复训练**：

**恢复策略设计**：
当前配置通过多个机制协同工作，实现从侧卧状态到直立状态的恢复：

**机制1：轮子角动量恢复**
- **物理原理**：角动量守恒（L_total = L_body + L_wheels = constant）
- **实现方式**：悬空轮子急加速 → 机身获得反向角动量 → 产生翻滚扭矩
- **触发条件**：
  - 悬空轮子检测（接触力 < 1.0 N）
  - 严重倾斜状态（projected_gravity Z < 0.5）
  - 奖励权重：2.0（高优先级）
- **应用场景**：
  - 右侧卧（roll ≈ +90°）：左侧轮子悬空 → 左侧轮子向前加速 → 向右翻滚
  - 左侧卧（roll ≈ -90°）：右侧轮子悬空 → 右侧轮子向前加速 → 向左翻滚

**机制2：机械臂惯性力矩恢复**
- **物理原理**：τ_inertial = I_arm × α_arm
- **实现方式**：机械臂快速甩动 → 产生惯性力矩 → 打破静态平衡
- **关键配置**：
  - arm_joint1 缩放因子：0.5（增大5倍）
  - 惯性力矩提升：25倍（(0.5/0.1)²）
  - 所有6个机械臂关节激活
- **应用场景**：
  - 侧卧状态：机械臂向一侧急甩 → 产生反向力矩 → 辅助翻滚
  - 与轮子角动量协同，产生复合恢复力矩

**机制3：自适应惩罚系统**
- **"疯狂探索"阶段**（Z < 0.5）：
  - 动作变化率惩罚降低 10 倍（-0.01 → -0.001）
  - 扭矩惩罚降低 10 倍（-2.5e-5 → -2.5e-6）
  - 接触惩罚降低 10 倍（-1.0 → -0.1）
  - 允许策略产生大幅度、快速的动作
- **平滑运动阶段**（Z > 0.8）：
  - 恢复完整惩罚
  - 确保运动平滑性和能量效率

**机制4：姿态直立奖励**
- **物理原理**：直接奖励直立姿态
- **实现方式**：reward = projected_gravity Z × 5.0
- **权重设计**：5.0（最高权重）
- **作用**：
  - 引导策略优先恢复直立姿态
  - Z = 1.0（完全直立）→ 奖励 = 5.0
  - Z = 0.0（完全倒下）→ 奖励 = 0.0

**初始状态随机化**：
- **Roll 角范围**：(-1.6, 1.6) rad = (±92°)
  - 覆盖从直立（0°）到完全侧卧（±90°）的整个区间
  - 强制策略学习各种倾斜状态的恢复
- **Pitch 角范围**：(-0.3, 0.3) rad = (±17°)
  - 限制前后倾，避免过度不稳定
- **高度范围**：(0.35, 0.5) m
  - 接近正常站立高度（0.40 m）
  - 避免从地面开始，降低恢复难度

**恢复流程**：

**阶段1：识别状态**
- 传感器获取姿态信息（projected_gravity）
- 判断是否严重倾斜（Z < 0.5）
- 识别悬空轮子（接触力 < 1.0 N）

**阶段2：选择恢复策略**
- **右侧卧**：
  - 悬空轮子：FL, RL
  - 机械臂：向左急甩
  - 轮子：FL, RL 向前急加速
  - 合力矩：向右翻滚
- **左侧卧**：
  - 悬空轮子：FR, RR
  - 机械臂：向右急甩
  - 轮子：FR, RR 向前急加速
  - 合力矩：向左翻滚

**阶段3：执行恢复动作**
- 利用自适应惩罚，允许大幅度动作
- 同时使用轮子角动量和机械臂惯性力矩
- 产生复合恢复力矩

**阶段4：稳定姿态**
- 姿态改善（Z 增加）
- upward 奖励增加（强化恢复行为）
- 进入过渡区域（0.5 ≤ Z ≤ 0.8）
- 惩罚权重逐渐恢复

**阶段5：完成恢复**
- 达到直立状态（Z > 0.8）
- 恢复完整惩罚，确保平滑运动
- 继续保持直立姿态

**关键设计理念**：
1. **多机制协同**：轮子角动量 + 机械臂惯性力矩 + 姿态奖励
2. **自适应控制**：根据姿态动态调整惩罚权重
3. **物理合理性**：利用角动量守恒和惯性原理
4. **训练高效性**：通过高权重和降低惩罚加速学习

- 检查：速度跟踪奖励权重是否足够
- 调整：增加 `track_lin_vel_xy_exp` 权重
- 原因：速度跟踪优先级不够高

**问题3：动作抖动严重**
- 检查：`action_rate_l2` 权重
- 调整：增加动作变化率惩罚
- 原因：动作平滑性约束不足

**问题4：能量消耗过高**
- 检查：扭矩和功率惩罚权重
- 调整：增加 `joint_torques_l2` 和 `joint_power` 权重
- 原因：能量效率约束不足

**问题5：侧卧恢复成功率低**（两段式恢复特有）
- 检查：
  - 初始 roll 角范围是否足够大（应包含 ±90°）
  - `wheel_angular_momentum` 权重是否足够（当前 2.0）
  - `upward` 奖励权重是否足够（当前 5.0）
  - 自适应惩罚系统是否正常工作
- 调整：
  - 增加 `wheel_angular_momentum` 权重（如从 2.0 增至 3.0）
  - 降低 `contact_threshold`（如从 1.0 降至 0.5，更灵敏地检测悬空轮子）
  - 检查 `arm_joint1` 缩放因子是否足够（当前 0.5）
- 原因：恢复机制不够强或参数设置不当

**问题6：轮子角动量奖励始终为 0**
- 检查：
  - `sensor_cfg.body_names` 是否正确配置（应为 ".*_foot"）
  - 轮子是否真的悬空（检查接触力数据）
  - 姿态是否满足 Z < 0.5 条件
- 调整：
  - 降低 `contact_threshold`（如从 1.0 降至 0.1）
  - 增加 roll 角范围
  - 检查 `wheel_joint_names` 是否正确
- 原因：配置错误或初始状态不符合预期

**问题7：机械臂未产生有效惯性力矩**
- 检查：
  - `arm_joint1` 缩放因子（当前 0.5）
  - 所有机械臂关节是否激活（当前 6 个全部激活）
  - 自适应惩罚系统是否允许大幅度动作
- 调整：
  - 进一步增加 `arm_joint1` 缩放因子（如从 0.5 增至 0.8）
  - 确认 `action_rate_adaptive` 的 `reduced_penalty_weight` 足够小
- 原因：缩放因子不够大或惩罚约束过严

**问题8：自适应惩罚系统未生效**
- 检查：
  - `orientation_threshold` 值（当前 0.5）
  - `reduced_penalty_weight` 是否正确设置
  - 姿态数据是否正确更新
- 调整：
  - 降低 `orientation_threshold`（如从 0.5 降至 0.3，更早触发降低惩罚）
  - 增加 `reduction_factor`（如从 0.1 降至 0.05，降低 20 倍）
- 原因：阈值设置不当或函数实现有问题

### 8.2 参数调优建议

**权重调整原则**：
1. 正奖励（速度跟踪）：确保足够大以引导学习
2. 安全性惩罚（关节限位、接触）：权重较大，严格约束
3. 效率惩罚（扭矩、功率）：权重适中，平衡性能和效率
4. 平滑性惩罚（动作率）：权重较小，避免过度约束

**参数调整方法**：
1. 单参数调整：一次只调整一个参数
2. 小步调整：每次调整幅度不超过50%
3. 观察奖励分布：确保奖励值在合理范围
4. 监控学习曲线：确保稳定收敛

- 所有 6 个机械臂关节激活
- arm_joint1 缩放因子 0.5（增大 5 倍）
- 允许动态甩动产生惯性力矩
